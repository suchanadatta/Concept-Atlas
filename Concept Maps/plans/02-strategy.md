# 02 — Strategy

## Chosen
**Static single-page app + vendored assets + custom threaded Python server on 0.0.0.0:8788.**

- Location: `Concept Maps/graph-ui/` (UI lives with its data corpus)
- Data: one pre-built `data/graph-data.json` (nodes+edges+queries+evidence+category colors) generated by `prepare_data.py` from `final/` — regeneration is one command
- Rendering: **Canvas** + d3-force (vendored d3@7.9.0 full bundle), quadtree hit-testing, LOD labels
- Design: "scholarly atlas" — parchment field, EB Garamond display, Inter UI, muted 9-category palette, category-clustered force layout (toggleable)
- Panels: left sidebar (search results, category filters, importance slider, relation legend), right detail panel (definition, aliases, stats, related concepts, evidence quotes), header (search, query mode, stats)
- Query mode: 43 corpus queries → highlight ranked concepts with relevance badges
- Hosting: `serve.py` (ThreadingHTTPServer, gzip, cache headers, /healthz) via `start.sh` (setsid nohup + pidfile); `stop.sh`; README documents manual start; crontab @reboot attempted for boot persistence

## Rejected alternatives
| Alternative | Why rejected |
|---|---|
| CDN-loaded libs | Intranet clients may lack internet; vendoring verified trivial |
| Cytoscape.js | Heavier (~400KB+), opinionated styling; d3-force gives finer control for the atlas aesthetic |
| React/Vite app | Build toolchain overkill for one static page; port 80/5173 already busy with Vite apps |
| Flask/FastAPI backend | No dynamic API needed — data is static JSON; stdlib http.server is dependency-free |
| Port 80/8080 | Occupied by existing services (verified) |
